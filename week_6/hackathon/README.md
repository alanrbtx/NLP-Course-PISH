# Хакатон: прикладная система на основе LLM

Илья Новицкий · 12 декабря 2026, 12:00–15:10 (после лекции блока 6)

Команды по 3–4 человека собирают работающий прототип и **честно оценивают** его. Побеждает не самая
сложная архитектура, а решение, у которого есть набор проверок, базовая линия и понятный ответ на вопрос
«насколько это лучше простого варианта и сколько стоит».

Стартовый каркас: [Хакатон — стартовый ноутбук.ipynb](<Хакатон — стартовый ноутбук.ipynb>) — клиент модели
с журналом, формат набора проверок, попарный судья с перестановкой, задержка, стоимость и `report.json`.

## Треки

### 1. Ассистент по документам (RAG)
Ответы на вопросы по коллекции документов со ссылками на источники и честным «нет ответа».

- Идеи: ассистент по материалам этого курса (лекции и ноутбуки); справочник по открытым нормативным
  документам; помощник по документации библиотеки; база знаний по Википедии (SberQuAD).
- Обязательная оценка: Recall@k поиска на размеченных вопросах, доля ответов, опирающихся на источник,
  доля корректных отказов на вопросах без ответа.
- База из курса: практика блока 5 и ДЗ 4.

### 2. Чат-бот поддержки
Классификация обращения, извлечение полей и ответ по правилам компании.

- Идеи: поддержка интернет-магазина (возвраты, доставка, оплата); запись к врачу; деканат.
- Обязательная оценка: точность классификации и полей, доля валидного JSON, попарное сравнение ответов
  с базовой линией, устойчивость к внедрению инструкций.
- База из курса: семинар по API, ДЗ 2.

### 3. Дообученная модель для узкой задачи
LoRA-адаптер небольшой открытой модели, который заменяет промпт с примерами или большую модель.

- Идеи: заголовки и аннотации новостей (Gazeta); разбор команд в JSON (MASSIVE); нормализация адресов
  и дат; перевод запроса на естественном языке в SQL; перенос стиля (официальный ↔ разговорный).
- Обязательная оценка: исходная модель и промпт с примерами против адаптера на одном наборе,
  попарное сравнение, проверка общих умений после дообучения.
- База из курса: семинар week_4 (LoRA и DPO в TRL).

### 4. Агент с инструментами
Модель планирует шаги и вызывает инструменты: поиск, базу данных, калькулятор, календарь.

- Идеи: аналитик по таблицам продаж (SQL); планировщик встреч по календарю; исследователь, который
  ищет по документам и считает.
- Обязательная оценка: доля решённых задач с автоматической проверкой ответа, среднее число шагов,
  поведение при ошибке инструмента. Инструменты только на чтение или с подтверждением действий.
- База из курса: практика блока 5 и ДЗ 4.

### 5. Быстрый и дешёвый сервис
Готовая модель в квантованном виде за OpenAI-совместимым API с измеренными задержкой, пропускной
способностью и стоимостью.

- Идеи: сервис классификации обращений на GGUF-модели; сравнение уровней квантизации и серверов;
  маршрутизация между малой и большой моделью.
- Обязательная оценка: качество относительно исходной модели, p50/p95 задержки под нагрузкой,
  стоимость миллиона токенов, анализ компромисса.
- База из курса: лекция блока 6 (квантизация, серверы, стоимость).

Своя тема возможна по согласованию до начала хакатона.

## Что сдать

1. Репозиторий: код, `requirements.txt` с фиксированными версиями, README с инструкцией запуска
   с нуля, описанием данных и их лицензий.
2. Набор проверок — не меньше 20 примеров, зафиксированный до экспериментов (хеш в `report.json`).
3. Отчёт: базовая линия и ваша система по основной метрике и попарно; задержка p50/p95;
   стоимость на 1000 запросов; 2–3 разобранные ошибки; известные ограничения.
4. Демонстрация и защита: 5 минут доклада и 2 минуты вопросов.

## Критерии оценки — 100 баллов

| Критерий | Баллы | Что смотрим |
|---|---:|---|
| Качество и честность оценки | 30 | Набор проверок, базовая линия, отсутствие подгонки под тест, проверка судьи |
| Инженерия и воспроизводимость | 20 | Запуск с нуля, версии, структура кода, обработка ошибок, журнал |
| Польза и демонстрация | 20 | Понятный сценарий использования, работающая демонстрация |
| Анализ ошибок и ограничений | 15 | Типы ошибок, что исправлено, что осталось и почему |
| Защита | 15 | Ясность доклада, ответы на вопросы, стоимость и задержка |

## План дня

| Время | Что делаем |

| До 12 декабря | Собрать команду, выбрать трек, скачать модели и данные, проверить доступ к API |
| 12:00–12:20 | Старт, уточнение задачи |
| 12:20–13:00 | Набор проверок и базовая линия от входа до ответа |
| 13:00 | Контрольная точка: показать базовую линию и первую оценку |
| 13:00–14:10 | Улучшения и сравнение версий |
| 14:10–14:30 | Отчёт и подготовка демонстрации |
| 14:30–15:10 | Защита: 5 минут доклада и 2 минуты вопросов |

Три часа — мало, поэтому решение должно быть маленьким: одна задача, один набор проверок, одно-два
улучшения относительно базовой линии. Лучше честно измеренный простой RAG, чем недоделанный агент.

## Правила

- Модели: открытые веса или выданный доступ к API. Ключи не попадают в репозиторий и выводы ноутбуков.
- Данные: открытые наборы с понятной лицензией или синтетические. Никаких персональных данных.
- Набор проверок не используется для подбора промптов «на глаз» — для этого держите отдельные примеры.
- Код семинаров и домашних заданий курса можно использовать свободно; заимствования из других проектов указываются.
